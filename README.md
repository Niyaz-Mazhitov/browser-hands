# browser-hands

MCP-сервер для Claude Code с одним инструментом `browse(url, goal?, steps?)`. Он сам выполняет в Chrome цель `goal`
или сценарий `steps` (шаги с дословными текстами): кликает, печатает, выбирает. В режиме attach агент работает в уже
открытой у вас вкладке, если в `url` задан только сайт или ровно эта страница, иначе открывает `url` в своей фоновой
вкладке. Действия выбирает модель Jev через OpenRouter. В ответ приходят статус, шаги, замеры времени, стоимость и
скриншот вкладки. Цикл взят из
[jev-ultrafast](https://github.com/browser-use/jev-ultrafast) (Browser Use, MIT, коммит
`1231850a0bf1a0c0341fe408ef1668dbbfdfac46`): атомарный снимок страницы, затем один запрос к Jev (операция и
спекулятивные цели), затем действие по наблюдаемому узлу. Что изменено: свой CDP-клиент на `websockets` вместо
browser-harness, OpenRouter вместо TypeSafe API, MCP-сервер и CLI вместо демо-инспектора, телеметрии нет.

## Установка

Нужны macOS, Google Chrome, [uv](https://docs.astral.sh/uv/) и ключ OpenRouter.

Из клона (версии зависимостей — из `uv.lock`); `<путь к клону>` — каталог, куда склонирован репозиторий:

```bash
cd <путь к клону>
uv sync
cp .env.example .env && chmod 600 .env   # вписать OPENROUTER_API_KEY=...
uv run --env-file .env browser-hands --help
```

Как инструмент uv (зависимости разрешаются заново, без `uv.lock`):

```bash
uv tool install <путь к клону>                           # команда browser-hands в ~/.local/bin
uv tool run --env-file <путь к клону>/.env browser-hands run --url … --goal …
uv tool uninstall browser-hands                          # откат
```

Ключ и `BROWSER_HANDS_*` читаются только из окружения, `.env` в окружение загружает `uv --env-file`. FastMCP
(`serve`) сам читает `.env` из рабочего каталога, но берёт оттуда только переменные `FASTMCP_*`.

## Режимы браузера

- **attach** (по умолчанию) — ваш Chrome с вашими куками. Один раз откройте `chrome://inspect/#remote-debugging`
  и включите удалённую отладку. При первом подключении Chrome спросит разрешение: нажмите «Разрешить». Окно
  появляется один раз на процесс сервера. Агент работает в вашей открытой вкладке или в своей фоновой (см. «Какую
  вкладку берёт агент»). Пока отладка включена, браузером может управлять любой локальный процесс.
- **launch** — отдельный Chrome с профилем `~/.cache/browser-hands/chrome-profile`, куки сохраняются между
  запусками. `--fresh-profile` даёт временный профиль, который удаляется по выходу. `BROWSER_HANDS_HEADLESS=1` или
  `--headless` запускают Chrome без окна.
- **ws** — готовый `ws://127.0.0.1:<port>/devtools/browser/<id>` в `BROWSER_HANDS_WS_URL` или `--ws`; важнее режима.

Автоматического перехода из attach в launch нет: если Chrome недоступен, `browse` вернёт `failed` с причиной.

### Какую вкладку берёт агент

В attach агент работает в вашей открытой вкладке, если в `url` задан только сайт или ровно эта страница:

- `url` — только сайт (`https://web.whatsapp.com`, путь пустой или `/`, без `?…`): подходит любая открытая вкладка
  этого сайта;
- `url` с путём или `?…` (`https://en.wikipedia.org/wiki/Python`): подходит только вкладка с тем же адресом (без
  `#…`). Сайт открыт на другой странице — агент открывает `url` в своей вкладке;
- сайт — хост вместе с портом (по умолчанию 443 для https, 80 для http): `localhost:5173` не берёт вкладку
  `localhost:3000`, `example.com` — вкладку `example.com:8443`.

В вашей вкладке агент:

- по `url` не переходит: начинает с того, что открыто;
- не закрывает её в конце, не меняет размер, не перезагружает и не переключает на неё окно; `keep_open` к ней не
  относится;
- из нескольких подходящих берёт ту, чей адрес совпадает с `url` (без `#…`), иначе первую по списку Chrome.

`browse` возвращает `failed`, не открывая своей вкладки и не вызывая Jev, если:

- все подходящие вкладки заняты: к ним подключён другой клиент — открыты DevTools, расширение или другая сессия
  browser-hands. Закройте его или вызовите с `new_tab=true`;
- подходящие вкладки открыты в нескольких профилях или окнах инкогнито, а вкладки ровно с адресом `url` нет (или их
  несколько). Оставьте одну или вызовите с `new_tab=true`.

Подходящей вкладки нет — агент открывает `url` в своей фоновой вкладке и закрывает её в конце (кроме `keep_open`).
`new_tab=true` (в CLI `--new-tab`) — всегда своя вкладка, даже если сайт открыт. В launch и ws вкладка всегда своя.
Остальные ваши вкладки агент не трогает.

Пока агент работает в вашей вкладке, не трогайте её: ваши клики и ввод смешаются с его действиями. Остановить агента —
Esc в Claude Code. Сайтам, которые держат одну активную вкладку (WhatsApp Web), передавайте в `url` только сайт и не
ставьте `new_tab`: своя вкладка отберёт сессию у вашей.

## Переменные

Пустое значение означает значение по умолчанию. Неверное значение — ошибка с именем переменной.

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `OPENROUTER_API_KEY` | — | ключ для Jev и текстовой модели; подставляется, только если адрес модели на `openrouter.ai` |
| `BROWSER_HANDS_MODE` | `attach` | `attach` или `launch` |
| `BROWSER_HANDS_WS_URL` | — | готовый ws-адрес браузера; важнее `MODE` |
| `BROWSER_HANDS_CHROME_DATA_DIR` | `~/Library/Application Support/Google/Chrome` | attach: где лежит `DevToolsActivePort` |
| `BROWSER_HANDS_LAUNCH_DATA_DIR` | `~/.cache/browser-hands/chrome-profile` | launch: профиль |
| `BROWSER_HANDS_CHROME_BINARY` | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` | launch: какой Chrome запускать |
| `BROWSER_HANDS_HEADLESS` | `0` | launch без окна (`1/true/yes`) |
| `BROWSER_HANDS_CONNECT_TIMEOUT_S` | `60` | сколько ждать подключения («Разрешить» в attach) |
| `BROWSER_HANDS_SCREENSHOT_QUALITY` | `60` | JPEG, 1–100 |
| `BROWSER_HANDS_SCREENSHOT_SCALE` | `1` | масштаб скриншота, (0; 1]; `0.5` — в 3–4 раза меньше байт |
| `BROWSER_HANDS_JEV_URL` | `https://openrouter.ai/api/v1/systemone` | адрес Jev |
| `BROWSER_HANDS_JEV_MODEL` | `jev-latest` | модель Jev |
| `BROWSER_HANDS_JEV_API_KEY` | `OPENROUTER_API_KEY` | отдельный ключ для Jev; обязателен, если `JEV_URL` не на `openrouter.ai` |
| `BROWSER_HANDS_TEXT_BASE_URL` | `https://openrouter.ai/api/v1` | OpenAI-совместимый адрес текстовой модели |
| `BROWSER_HANDS_TEXT_MODEL` | `inception/mercury-2.5` | модель, которая пишет текст для `TYPE_TEXT` |
| `BROWSER_HANDS_TEXT_API_KEY` | `OPENROUTER_API_KEY` | отдельный ключ для текстовой модели; обязателен, если `TEXT_BASE_URL` не на `openrouter.ai` |
| `BROWSER_HANDS_TEXT_REASONING` | `none` | `none` или `low` |
| `BROWSER_HANDS_JEV_TIMEOUT_S` | `10` | потолок одного запроса к Jev, секунды, по часам на весь ответ; не дольше дедлайна прогона |
| `BROWSER_HANDS_TEXT_TIMEOUT_S` | `8` | то же для текстовой модели; не уложилась — один повтор |
| `BROWSER_HANDS_MAX_STEPS` | `25` | лимит шагов по умолчанию, 1–50 |
| `BROWSER_HANDS_TIMEOUT_S` | `90` | дедлайн прогона по умолчанию, секунды, (0; 300] |
| `BROWSER_HANDS_LOG` | `INFO` | уровень логов; логи идут только в stderr; полный url, цель и сценарий — только на `DEBUG` |

## CLI

```bash
uv run --env-file .env browser-hands run --url https://en.wikipedia.org/wiki/Main_Page \
  --goal "Find and open the Wikipedia article about Gödel's incompleteness theorems." --screenshot traces/run.jpg
```

Сценарий (формат — в «Сценарий (`steps`)») — файлом, например `wiki-steps.json`; `--goal` при сценарии необязателен:

```json
[
  {"do": "Type the query into the Wikipedia search box", "text": "Gödel's incompleteness theorems"},
  {"do": "Open the matching article from the suggestions or search results"}
]
```

```bash
uv run --env-file .env browser-hands run --url https://en.wikipedia.org/wiki/Main_Page --steps-file wiki-steps.json
```

Флаги `run`: `--goal` (нужен, если нет сценария), `--steps-file P` (JSON-список `{do, text?}`), `--step DO`
(повторяемый; шаг без текста, добавляется после шагов файла), `--max-steps N` (≤ 50), `--timeout S` (≤ 300),
`--keep-open`, `--new-tab` (своя вкладка, даже если сайт открыт), `--mode attach|launch`, `--headless`, `--ws URL`,
`--data-dir P`, `--fresh-profile`, `--json` (RunResult без байтов скриншота, поле `tab`: `user|new|null`; при сценарии —
`scenario_done`, `scenario_total`, `scenario_step` у шагов и входной сценарий в `scenario`), `--screenshot out.jpg`.
Флаги важнее переменных. Код выхода: `0` при `done`, `2` в остальных случаях; ошибка в сценарии (файл, JSON, лимиты)
— одна строка в stderr и `2`, Chrome не запускается. `browser-hands serve` запускает MCP-сервер по stdio и принимает те
же флаги браузера. Команда `run` заменяет `examples/run.py` из jev-ultrafast.

## Claude Code

Регистрация (для всех проектов пользователя) — из каталога клона: `$(pwd)` при регистрации раскрывается в абсолютный
путь, и он сохраняется в `~/.claude.json`.

```bash
cd <путь к клону>
claude mcp add -s user browser-hands -- uv run --frozen --directory "$(pwd)" --env-file "$(pwd)/.env" browser-hands serve
```

Проверка: `claude mcp list` показывает `browser-hands: … - ✓ Connected`. Ключ не попадает в `~/.claude.json`: при
каждом запуске его читает `uv` из `.env`. Режим меняется в `.env` (`BROWSER_HANDS_MODE=launch`) или флагом после
`serve`. Если сервер поставлен через `uv tool install`, после `--` пишется
`uv tool run --env-file <путь к клону>/.env browser-hands serve`.

Откат: `claude mcp remove -s user browser-hands`.

Как работает сервер:

- `browse(url, goal?, steps?, max_steps?, timeout_seconds?, keep_open?, new_tab?)`: нужен `goal`, `steps` или оба
  (см. «Сценарий (`steps`)»); ни того ни другого — `failed` без Chrome. Chrome и HTTP-клиенты создаются при первом
  вызове и живут, пока жив процесс сервера. Мёртвое соединение переподключается при следующем вызове.
- Второй `browse`, запущенный параллельно, ждёт окончания первого.
- Отмена (Esc) останавливает агента между шагами (начатый шаг доходит до конца) с `failed: cancelled`. Отменённый
  вызов, который ещё ждал в очереди, не запускается.
- Лимиты одного вызова: `max_steps` ≤ 50, `timeout_seconds` ≤ 300.
- Стартовый `url` — только `http://`, `https://` или `about:blank`; адрес без схемы (`example.com`) дополняется до
  `https://`. Другие схемы (`file:`, `chrome:`, `data:`, `javascript:` …) дают `failed`, вкладка не открывается.
- SIGTERM, SIGINT и SIGHUP: сервер отменяет прогон и сразу закрывает Chrome (launch — процесс, attach — соединение;
  вашу вкладку только отпускает, не закрывает).
- Ошибки (нет ключа, Chrome недоступен, ядро не отвечает) приходят текстом `status: failed` и `error: …`, а не
  исключением. Неверные аргументы (шагов больше 20, лишний ключ в шаге, пустой `do`) — ошибка инструмента одной
  строкой: `неверные аргументы browse — step 2 url: Extra inputs are not permitted (allowed: do, text)`.

### Сценарий (`steps`)

Когда давать `steps`, а не только `goal`: задача из нескольких шагов (найти чат, открыть, написать, отправить) или
текст, который надо напечатать точно (сообщение, запрос, поле формы). По одной `goal` текст для поля пишет текстовая
модель, и он может отличаться от задуманного; текст шага печатается как есть.

Формат — список шагов `{"do": "…", "text": "…"}`:

- `do` — что сделать на этом шаге, **по-английски**: Jev обучен в основном на английском и точнее на нём. Называйте
  поле или кнопку так, как они подписаны на странице («the chat search box», «the Send button»). Для шагов без `text`
  добавляйте видимый признак готовности — «Send the message (done when it appears in the chat)», «Submit the form
  (done when a thank-you message is shown)»: по нему Jev увереннее закрывает шаг, и реже бывает `unconfirmed`;
- `text` — необязательный текст, который печатается **дословно** (любой язык, эмодзи, пробелы по краям). Он вводится
  только в поле, которое на этом шаге выбрала модель, с той же проверкой фокуса, что и обычный ввод, и больше никуда;
  текстовой модели тексты шагов не передаются ни на каком шаге. Если на шаге без `text` модель решила печатать, текст
  пишет текстовая модель по `goal` и `do` шага; без `goal` прогон останавливается — `blocked` с ошибкой
  `step k of M: no text given for typing`;
- лимиты: до 20 шагов (и не больше `max_steps`), `do` — 1–300 символов, `text` — 1–2000 символов; другие ключи —
  ошибка;
- `goal` вместе со `steps` — общая цель, которую Jev видит на каждом шаге.

Как идёт прогон: Jev на каждом шаге видит текущий шаг («Step 2 of 4: …»), выполненные и оставшиеся. Шаг выполнен,
когда Jev по видимой странице отвечает «да» с вероятностью не ниже 0,75; шаг с `text` закрывается после ввода, если поле
на свежем снимке показывает этот текст. Если сайт перерисовал поле и текст пропал, Jev решает заново по свежей странице
(можно напечатать ещё раз); после 2 повторных вводов прогон заканчивается `blocked` с ошибкой `step k of M: typed text
does not stay in the field`. На шаг — не больше 6 действий, иначе прогон заканчивается `step_limit`.

Если Jev ответил «шаг сделан» (DONE) без уверенного «да», агент ничего больше не нажимает: ждёт тишины страницы и
спрашивает ещё раз, разрешая только DONE, WAIT и BLOCKED. Не подтвердилось и тогда — прогон заканчивается `unconfirmed`:
шаг, вероятно, выполнен, проверьте по скриншоту.

В ответе — `сценарий: k из M выполнено`, при остановке — `остановился на шаге N из M: <do>` (при `unconfirmed` — `шаг
N из M не подтверждён (вероятно, выполнен — проверь скриншот): <do>`), у действий — номер шага сценария `[шаг k]`.
Строка `steps: N` в ответе — по-прежнему число действий, а не шагов сценария.

Пример — сообщение в WhatsApp Web (вкладка пользователя, `url` — только сайт):

```python
browse("https://web.whatsapp.com", steps=[
    {"do": "Type the chat name into the chat search box", "text": "Рабочий"},
    {"do": "Open the chat named «Рабочий»"},
    {"do": "Type the message into the message box", "text": "это я через агента, проверка 👋"},
    {"do": "Send the message"},
])
```

Шаг 4 отправляет сообщение настоящему собеседнику — это необратимо. Без него агент остановится с набранным текстом:
проверьте скриншот и отправьте сами.

## Ответ `browse` и как проверять результат

Текст ответа: `status` (`done|blocked|failed|timeout|step_limit|unconfirmed`), `error`, `url`, `title`, вкладка,
список шагов `N. OP цель — "текст"`, `cost: $…` (сумма `usage.cost` по шагам), `elapsed Xs (model / text / browser /
wait)`. Строка вкладки — `вкладка: твоя (<хост>)` (ваша открытая вкладка) или `вкладка: новая` (своя; `, оставлена
открытой` при `keep_open`). Если до вкладки не дошло (нет ключа, Chrome недоступен), строки нет. При сценарии сразу за
`status` и `error` — `сценарий: k из M выполнено` и, если прогон не `done`, `остановился на шаге N из M: <do>`; у шагов
— `[шаг k]`. `unconfirmed` бывает только в сценарии: шаг, вероятно, выполнен, но модель этого не подтвердила — смотрите
скриншот. К тексту приложен JPEG той же вкладки на момент окончания: своей — 1120×780, вашей — до ~1120 px по ширине в
пропорциях её окна.

Экран загрузки: пока на странице нет ни одного поля, кнопки или списка, агент ждёт и Jev не вызывает: в начале
прогона — до 25 с, в середине (после первого решения Jev) — одно ожидание следующего изменения страницы, не дольше
дедлайна. Это время идёт в `wait`,
`model calls` не растёт. Потом Jev вызывается как обычно: страница без элементов бывает и по замыслу.

`done` означает только, что модель сочла цель достигнутой. Результат надо проверять по скриншоту и `url`.

## Безопасность и приватность

- **Что уходит в OpenRouter** (Jev и текстовой модели) на каждом шаге: `goal`, сценарий `steps` (`do` и `text`; `text` —
  только Jev), url и title страницы, видимый текст до 6000 символов, подписи элементов, значения видимых полей (кроме
  `password`, `hidden` и `file`), последние шаги.
- **Скриншот** вкладки в конце прогона попадает в контекст Claude.
- **Ваша вкладка (attach).** Снимок и текст вашей открытой вкладки уходят в Jev (OpenRouter) так же, как своей, —
  включая всё, что на экране рядом с целью (соседние чаты, список писем); скриншот — в контекст Claude. Агент действует
  в вашей сессии сайта. Чтобы не отдавать то, что открыто у вас, — `new_tab=true` (`--new-tab`); чтобы не отдавать и
  куки — `--mode launch`.
- **Ввод заменяет содержимое поля:** агент выделяет всё в поле и вставляет свой текст — неотправленный черновик в этом
  поле сотрётся.
- **Ваша вкладка активна для сайта:** на время работы в ней агент включает focus emulation, и сайт считает вкладку
  активной — мессенджер может отметить сообщения прочитанными и показать вас «в сети».
- **attach — это ваши куки.** Агент действует от вашего имени на всех сайтах, где вы вошли. Текст страницы идёт в
  модель, поэтому страница может управлять агентом через prompt injection. Для незнакомых сайтов — `--mode launch`
  или `--fresh-profile`.
- **Необратимое не поручать:** оплаты, отправку писем и сообщений. Или ставить цель «заполни форму и остановись перед
  отправкой» (в сценарии — не давать шаг отправки) и проверять по скриншоту.
- **Потолки:** 50 шагов и 300 с на прогон. Отмена (Esc) останавливает агента между шагами.
- **Ключи** — только из окружения, в логи и `repr` не попадают. `OPENROUTER_API_KEY` отправляется только на
  `openrouter.ai`; для другого адреса модели нужен свой `BROWSER_HANDS_JEV_API_KEY` или `BROWSER_HANDS_TEXT_API_KEY`.
  Логи HTTP-библиотек (`hpack`, `h2`, `httpcore`, `httpx`) не ниже `WARNING` даже при `BROWSER_HANDS_LOG=DEBUG`.
- **Логи:** на `INFO` — только хост стартового адреса и число шагов сценария; полный url, цель и сценарий (`do`,
  `text`) — на `DEBUG`.
- **Известное ограничение:** снимок страницы и проверка, не перекрыт ли элемент, выполняются в контексте страницы
  (без isolated world). Враждебная страница может их обмануть: подменить то, что видит агент, и то, куда он кликнет.

## Ограничения

- Агент не видит iframe, shadow DOM и canvas: снимок страницы их не читает.
- Загрузка файлов, всплывающие окна и новые вкладки (`target=_blank`) не поддерживаются. Новая вкладка остаётся
  открытой, закройте её вручную.
- Не поддерживаются вложенная прокрутка и сложные клавиатурные виджеты. Имена элементов берутся из распространённых
  HTML/ARIA-атрибутов, а не по полной спецификации accessible name.
- Если сервер упал или соединение оборвалось, вкладка агента может остаться открытой. Закройте её вручную.
- Фоновые вкладки (своя в attach и ваша, если она не на переднем плане) Chrome замедляет: страницы с логикой на
  `setTimeout` могут «ждать» дольше.
- В вашей вкладке агент по `url` не переходит: начинает с того, что открыто.
- Две вкладки одного сайта: агент может взять не ту (правило — в «Какую вкладку берёт агент»). Закройте лишнюю или
  передайте в `url` точный адрес нужной.
- Если сервер убит `kill -9` во время работы в вашей вкладке, она может считать себя в фокусе, а другие сессии
  browser-hands — занятой (метка `__bhOwner` в странице): перезагрузите её.
- Страница без полей, кнопок и списков по замыслу стартует на 25 с позже (ожидание экрана загрузки); пустой экран в
  середине работы (например, прокрутили за все кнопки) — одно ожидание следующего изменения страницы. После каждого действия (и загрузки страницы)
  агент ждёт готовности страницы по событиям, а не по времени: два кадра подряд без изменений DOM, завершения запросов
  своей вкладки, загрузки документа и шрифтов, конечных анимаций и снятия `aria-busy`; после `WAIT` — сначала
  следующего изменения. Предохранитель одного ожидания — 1,5 с: страница, которая меняется каждый кадр или держит
  запрос (long-poll), добавляет до 1,5 с на шаг; таймер страницы без сети (`setTimeout`) ожидание не держит. Если
  ответа на запрос, начатый действием, нет и после предохранителя, перед следующим решением агент ещё раз ждёт
  изменения страницы (до 1,5 с, одно такое ожидание на действие), а Jev видит, сколько запросов ещё в пути. Три
  действия подряд без изменений страницы — ещё одно ожидание изменения и свежий снимок, потом `blocked` (пока запросы
  этих действий в пути — ждёт снова). На BLOCKED переспрашивает один раз; на невалидный ответ текстовой модели, ошибку
  провайдера или таймаут повторяет запрос один раз.
- Режим цели: текст, напечатанный в поле, должен оставаться там, пока его не использовали (клик не по полю, новый ввод
  в то же поле). Сайт пересоздал поле и текст пропал — агент не нажимает Send и не завершает прогон `done`, а печатает
  тот же текст снова (без повторного запроса к текстовой модели); после 2 повторов — `blocked` с ошибкой `typed text
  does not stay in the field '<поле>'`.
- Запрос к модели ограничен по часам целиком: Jev — 10 с, текстовая модель — 8 с (`BROWSER_HANDS_JEV_TIMEOUT_S`,
  `BROWSER_HANDS_TEXT_TIMEOUT_S`), не дольше дедлайна прогона, даже если провайдер держит соединение пробелами.
  Ответ 200 с `error` в теле — ошибка провайдера: запрос к Jev повторяется, как при 429/503.
- Каждый скриншот в ответе занимает 110–200 КБ base64 в контексте. `BROWSER_HANDS_SCREENSHOT_SCALE=0.5` уменьшает его.
- Сценарий: шаг с `text` считается выполненным, когда после ввода текст виден в поле, куда его напечатали. Если модель
  выбрала не то поле (поиск вместо сообщения), сценарий пойдёт дальше с неверным состоянием — называйте поле в `do` и
  проверяйте скриншот. «Шаг выполнен» решает модель по видимой странице: она может закрыть шаг рано или не закрыть его
  вовсе (`step_limit`, `unconfirmed`).
- Действие (клик, ввод, выбор), в котором модель уверена меньше чем на 0,3, агент не выполняет: ждёт тишины страницы и
  спрашивает ещё раз; второе такое решение подряд — `blocked` с ошибкой `uncertain action: …`. Так в обоих режимах.

## Разработка

- `bash scripts/check.sh` — ruff, проверка формата, pytest (офлайн, без ключей) и `node --check` для `snapshot.js`.
- `uv run --env-file .env python scripts/live_wikipedia.py` — живая проверка ядра: launch, headless, стоит доли цента.
- `uv run --env-file .env python scripts/bench.py --runs 5 --headless --fresh-profile --url … --goal …` —
  бенчмарк на тёплом Chrome: таблица, медиана и p95 по `elapsed/model/text/browser/wait`, сумма cost, JSONL в
  `traces/`. Платный.
- `uv run --env-file .env python scripts/eval.py --runs 10 --label <метка>` — стенд надёжности на локальных страницах
  `tests/fixtures/`: WhatsApp-подобный чат (поиск с задержкой, со спиннером и без, экран загрузки; `search-remount` —
  поле сообщения пересоздаётся через 1,6 с после открытия чата и текст пропадает, после Send статус «Sending…» 1,5 с,
  у исходящих кнопки «HH:MM Sent») и обычная форма.
  Chrome всегда свой (launch, headless, временный профиль), внешней сети у страниц нет. Успех проверяется по DOM:
  страница сама отчитывается стенду, статус агента на это не влияет. Итог — строка на прогон, сводка по задаче
  (verified и done k/N, медиана и p95 `elapsed`/`wait`, вызовы Jev и текстовой модели, стоимость, причины неудач) и
  JSONL в `traces/eval-<ts>.jsonl` с решениями Jev (что было на странице и что выбрано), историей отчётов страницы
  (`reports`: открытый чат, поиск, отправленные, текст поля) и запросами страницы к стенду (`api_calls`) — у всех
  `t_ms` от одного старта. Платный; `--tasks search,form` — часть задач, `--max-cost` — потолок суммы, `--delay` —
  другая задержка поиска, `--remount` — другое время пересоздания поля в `search-remount` (список —
  несколько пересозданий), `--sendstatus` — другое время «Sending…», `--net 0|1` — как страница ждёт «сервер».
  `--mode goal` (по умолчанию) даёт агенту цель задачи, `--mode scenario` —
  её сценарий `steps` без цели; сравнить режимы — два прогона с одними
  задачами: `--mode goal --label goal` и `--mode scenario --label scenario`. `--tasks all` добавляет `wiki` (статья
  Википедии, внешняя сеть, проверка по итоговому `url`). `uv run --frozen python scripts/eval.py --fixtures-only` —
  бесплатно, без моделей: скриптовые действия на настоящем Chrome проверяют, что страницы стенда ведут себя как
  задумано (страница задачи и варианты `net=0`, `remount=800,1600`; с `--delay`/`--remount`/`--sendstatus`/`--net` —
  одна страница с ними).
- Параметры `app.html`: `delay` — задержка результатов поиска (700 мс), `net=1` (по умолчанию) — поиск и подтверждение
  Send идут настоящими запросами к серверу стенда (`/api/search`, `/api/send`, пауза — на сервере; сигнал «сеть» для
  ожидания агента проверяем), `net=0` — те же задержки таймерами; `remount=<мс>[,<мс>…]` — пересоздания поля
  сообщения после открытия чата, всегда таймером (у WhatsApp это событие websocket), `remount=800,1600` — два;
  `sendstatus` — время «Sending…»; `senddelay` — подтверждение Send без статуса (300 мс); `boot`, `spinner`. Отчёт
  страницы несёт и разобранные параметры: стенд сверяет их с адресом, расхождение — неуспех «стенд: …».
- `uv run --env-file .env python scripts/eval.py --sweep axes --runs 5 --mode goal,scenario --label <метка>
  --max-cost 0.25` — развёртка параметров чата (docs/plan-waits.md §7.3): по осям `delay` 0, 500, 1500, 3000 мс при
  `net=1` и `net=0`, `remount` 0–3000 мс шагом 500 (delay 700, sendstatus 1500) и `sendstatus` 0 / 1500 при remount 0
  и 1600 — 18 ячеек; ≈180 прогонов, ≈$0,22, ≈25 мин. Ячейка — параметры в `start_url` и в строке JSONL (`cell`,
  `params`, `axes`); каждый прогон проверяется по DOM своей страницы. Прогоны по кругу (круг — все ячейки × режимы),
  поэтому обрыв по `--max-cost` оставляет ячейки поровну. Оси меняются `--delay-range`, `--remount-range` (`a:b:шаг`
  или список), `--sendstatus`, `--net`; `--sweep grid` — полное произведение; задача по умолчанию — `search-remount`.
  Выход 0 — сделаны все прогоны (неудачи в развёртке — данные). Бесплатно проверить каждую ячейку скриптом:
  `uv run --frozen python scripts/eval.py --fixtures-only --sweep axes` (≈1,5 мин).
- `uv run --frozen python scripts/sweep_report.py traces/eval-<ts>.jsonl [ещё.jsonl] [--out traces/sweep.md]` — отчёт
  развёртки: по каждой оси и режиму — успех k/N с интервалом Уилсона 95 %, медиана и p95 `elapsed` и `wait`,
  ASCII-кривая доли успехов; два файла — колонки «было/стало». `--fuse [--wa traces/wa-observe-*.json]` —
  распределение «действие → последнее изменение страницы» (p50/p90/p99) и рекомендуемое `wait_fuse_s`.
