# browser-hands — решения

## Решения 25.09.2026

По §0 `docs/plan.md`, приняты пользователем.

1. Контракт — в ветке `feat/initial` (`main` — только `.gitignore`). Исполнители ветвятся от неё: `feat/core`, `feat/shell`,
   и вливаются обратно в `feat/initial`.
2. CDP-клиент — свой, синхронный, на `websockets` (без Playwright).
3. Ключ для сервера — через `uv run --env-file <proj>/.env` в команде регистрации; не через `claude mcp add -e`.
4. Скриншот в ответе `browse` — JPEG 1120×780, quality 60. Масштаб — `BROWSER_HANDS_SCREENSHOT_SCALE`, по умолчанию 1.
5. Профиль в режиме launch — постоянный `~/.cache/browser-hands/chrome-profile` по умолчанию; временный — флаг `--fresh-profile`.
6. Второй параллельный `browse` ждёт в очереди (один лок на сервер), а не возвращает `failed: busy`.

Уточнения контракта при контрактном коммите (Шаг 0):

- `types.py`: убран неиспользуемый импорт `field` (иначе `ruff` F401); `Timing.__add__` реализован (поэлементная сумма).
- `config.py`: `jev_api_key`, `text_api_key` — `field(default="", repr=False)`, чтобы ключи не попадали в `repr` с первого
  коммита (§10 «repr конфигов без ключей», тест 2.2).
- `.python-version` = `3.12`: все три worktree и CI (2.5) — на минимальной поддерживаемой версии; без файла uv выбирает 3.13.
- `pyproject.toml`: `[tool.ruff.format] exclude = ["*.md"]` — ruff 0.16.9 форматирует python-блоки в Markdown, и
  `ruff format --check .` из `scripts/check.sh` (2.5) падал бы на `docs/plan.md`.
- `.env.example`: переменные `BROWSER_HANDS_*` — закомментированы со значениями по умолчанию (список — §7, п. 2.2 и 2.1);
  незакомментирован только пустой `OPENROUTER_API_KEY=`.

## Пакет 1 (ядро, `feat/core`)

Отклонения от плана и уточнения; итоги живых прогонов — `docs/core-notes.md`.

- `cdp.py`: `websockets.sync.client.connect(..., proxy=None, compression=None, ping_interval=None)`. websockets 15 по
  умолчанию берёт прокси из env — с `HTTPS_PROXY` (проверка 1.8) локальный CDP пошёл бы через прокси. Сжатие для
  локального ws — лишний CPU на снимках; keepalive не нужен — живость проверяет `Chrome.alive()`.
- `cdp.py`: иерархия ошибок — `CDPError` (наследует `RuntimeError`, как ошибки CDP в источнике), `CDPTimeout`
  (`TimeoutError`), `ChromeDisconnected` (`ConnectionError`), `TabGone`; `Target.targetCrashed` сопоставляется с сессией
  по `targetId` из `attachToTarget`; ответ «Session … not found» → `TabGone`; запоздалый ответ после таймаута пропускается.
- `chrome.py`: `Chrome.__init__` принимает необязательные `client_factory`/`launcher` (для тестов), `new_tab()` —
  необязательные `screenshot_quality`/`screenshot_scale` (значения из `Agent` важнее конфига). Совместимо с §4.
- `chrome.py`: вкладки, не закрытые из-за обрыва ws, закрываются при следующем `connect()` по `targetId` (в §10 считалось,
  что отличить нельзя, — по url нельзя, по `targetId` можно). `keep_open`-вкладки из списка удаляются и не закрываются.
- `chrome.py`: `launch_chrome` до удаления DevToolsActivePort проверяет `SingletonLock` профиля (`<host>-<pid>`, pid
  жив) → `ChromeUnavailable` «профиль занят Chrome (pid N)». Иначе новый Chrome отдал бы управление оставшемуся от
  прошлого сервера и вышел, а мы стёрли бы его файл порта. Устаревший замок (pid мёртв) запуску не мешает.
- `browser.py`: `Tab.observe(screenshot=False)` по умолчанию (у источника `True`; агент снимков по ходу не делает).
  Новые `Tab.release()` (keep_open: `Target.detachFromTarget` — Chrome снимает эмуляцию viewport, вкладка остаётся
  обычной) и `NavigationFailed` (`Page.navigate` вернул `errorText` → `failed` сразу, без вызовов моделей).
- `browser.py`: CDP-вызов, завершившийся `StalePage` (документ грузится), учитывается в `wait_ms`, а не в `browser_ms`:
  после клика по ссылке Chrome держит `Runtime.evaluate` ~1 с (замер: 988–1297 мс), и `browser_ms` выглядел бы как
  медленный CDP. Таймауты CDP-вызовов агента ограничены остатком дедлайна (не меньше 1 с).
- `model.py`: `choose(clients, state, goal, history, *, timeout)` и `field_text(clients, context, *, timeout)` — конфиг
  берётся из `clients.config` (в плане отдельный аргумент `config` дублировал его). `Decision`/`TextHelper` — dataclass.
- `model.py`: `warmup()` — `HEAD <origin>/` без ключа (а не `GET /api/v1/auth/key`): ключ не уходит лишний раз, работает
  для любого хоста; блокирующий, ≤2 с — поток создаёт вызывающий (сервер, live-скрипт).
- `model.py`: при HTTP-ошибке в текст добавляется `error.message` провайдера (≤200 символов, без ключа); таймаут модели —
  `ModelTimeout` (`TimeoutError`); сообщение «Invalid TypeSafe response» → «Invalid Jev response».
- `agent.py`: если и повторный снимок после `StalePage` устарел (страница грузится дольше 10×20 мс), прогон не падает
  (у источника исключение уходило наружу): следующий тик снова проверяет свежесть, до дедлайна; моделей не вызывает.
- `agent.py`: бюджет решений Jev — `2 × max_steps` (как `MAX_STEPS*2` у источника) → `step_limit`; `max_steps`
  проверяется перед исполнением действия, как у источника, — DONE после последнего шага ещё возможен.
- `agent.py`: `RunResult.error` заполняется и для `blocked`/`step_limit` (причина); `timing`/`cost` — весь прогон, включая
  отброшенные решения и DONE; `Step.timing`/`Step.cost` — всё с прошлого шага; `model_calls` — Jev + текст.
- `tests/fake_cdp.py` — новый файл Пакета 1 (фейковый CDP-сервер для `test_cdp.py`/`test_chrome.py`), в §3 его не было.
- Живьём проверен только `launch` + headless + временный профиль (3 платных прогона, все `done`, 6,6–10,1 с);
  `attach` — только офлайн-тестами (DevToolsActivePort во временном каталоге, фейковый ws-сервер, отказ соединения).

## Пакет 2 (обвязка), 25.09.2026 — отклонения от плана

Проверено на `mcp 1.30.0` из `uv.lock` (в плане — 1.28.1 из кэша). API тот же: `FastMCP(name, instructions=)`,
`Image(data=, format=)`, `run("stdio")`. `_convert_to_content` превращает `list[str | Image]` в
`[TextContent, ImageContent]`. Инструмент зарегистрирован с `structured_output=False`, поэтому `outputSchema` у него нет.

1. **`browse` async, ядро — в `anyio.to_thread.run_sync(..., abandon_on_cancel=True)`.** FastMCP 1.30 вызывает
   синхронный инструмент прямо в event loop (`func_metadata.call_fn_with_arg_validation`: `fn(**args)`), поэтому
   прогон на 90 с блокировал бы ping и cancel. Лок — `threading.Lock` в `BrowseService`, второй вызов ждёт в своём
   потоке. Отмена (Esc) прогон не прерывает: у Agent нет отмены. Прогон доходит до дедлайна, следующий `browse` ждёт.
2. **Параметры `browse`:** `max_steps: int = settings.run.max_steps`, `timeout_seconds: float = settings.run.timeout_s`,
   `keep_open: bool = settings.run.keep_open` вместо `… | None = None`. В схеме видны настоящие значения по
   умолчанию; `ge=1`, `gt=0`; у `url` и `goal` `min_length=1`. Описание `browse` — 125 символов, `instructions` — 92.
3. **`BrowseService` в `server.py`** — ленивое ядро, лок, `connect()` на каждый вызов, `warmup()` один раз в потоке,
   любые ошибки дают `RunResult(status="failed")`. Им пользуются MCP, `cli run` и `scripts/bench.py`.
   `create_server(settings, *, chrome_factory, agent_factory, clients_factory)` — как в плане. Добавлен
   `build_server(service)`: `serve` сам держит сервис и закрывает его.
4. **Порядок проверок в `browse`:** сначала импорт модулей ядра, потом ключ. До слияния
   `browser-hands run --url x --goal y` без `.env` отвечает `error: модуль browser_hands.chrome ещё не готов`
   (код 2, без traceback). Ошибки из модулей `browser_hands.*` (ConfigError, ChromeUnavailable…) показываются
   текстом, чужие — `Тип: текст`, трейс уходит в stderr.
5. **Выход `serve`.** Конец stdin → штатный выход, в `finally` вызывается `service.close()`. SIGTERM, SIGINT и SIGHUP →
   `service.close()` и `os._exit(0)`: штатный выход по сигналу завис бы на чтении stdin в потоке anyio. `atexit` не
   используется. `close()` ждёт идущий `browse` не дольше 3 с, потом закрывает соединения всё равно. Проверено:
   выход по EOF за 0,04 с, по SIGTERM — сразу.
6. **`--fresh-profile` подразумевает launch** (CLI и bench). С `--mode attach` или `--ws` — ошибка. Команда
   бенчмарка из §8 (3.3) идёт без `--mode`.
7. **Текст ответа:** строка `error` стоит сразу после `status`, а не в конце. Добавлены `cost: $X (model calls: N)`,
   `tab: оставлена открытой`, `screenshot: нет`. Пометки `cost (Jev only)` нет: RunResult не говорит, пришла ли
   стоимость текстовой модели. Это решается в ядре (1.8). URL без схемы дополняется `https://`.
8. **`BROWSER_HANDS_LOG`** в `Settings` не хранится: в контракте нет поля. `from_env` только проверяет значение,
   уровень читает `logging.get_logger()` из окружения. У FastMCP уровень `WARNING` (`DEBUG` при
   `BROWSER_HANDS_LOG=DEBUG`), чтобы не шуметь строками «Processing request…».
9. **`Settings.validate()`** в launch (без ws) проверяет ещё и наличие `chrome_binary`.
10. **`tests/__init__.py`** (нет в §3): без него `from tests.fakes import …` не импортируется под pytest (rootdir не в
    `sys.path`). На тесты ядра не влияет.
11. **`scripts/check.sh`** запускает `uv run --locked`; `node --check` пропускается, пока `snapshot.js` нет (до
    слияния). CI (`.github/workflows/ci.yml`) — `uv sync --locked` и `check.sh`.
12. **`examples/run.py` из исходника не перенесён:** его заменяет `browser-hands run` (одна цель, Agent принимает
    одну `goal`).
13. **`serverInfo.version`** = версия SDK `mcp` (1.30.0): FastMCP не принимает версию сервера, приватное поле не трогали.
14. **`uv tool install`** разрешает зависимости заново, без `uv.lock`. Проверено во временных `UV_TOOL_DIR` и
    `UV_TOOL_BIN_DIR`: встал `mcp 1.30.0`, `uv tool run --env-file … browser-hands serve` отвечает на `initialize` и
    `tools/list`. В README основной путь — запуск из клона с `--frozen`.

## Исправления после ревью — ядро

25.09.2026, ветка `feat/core`.

1. **Отмена.** `Agent(..., cancel: threading.Event | None = None)` (keyword-only). `cancel.is_set()` проверяется перед
   каждым вызовом модели (Jev и текст) и каждым действием (новая вкладка, навигация, `tab.act`), а также в начале тика.
   Итог — `status="failed"`, `error="cancelled"` (контракт `Status` не менялся). Финальный скриншот при отмене не
   снимается: вызывающий уже не ждёт, вкладку освобождаем сразу. Вкладка закрывается в `finally` как обычно, при
   `keep_open` — отсоединяется. Идущий HTTP-запрос к модели не прерывается: отмена срабатывает после него, до действия.
2. **`CDPClient.call`: таймаут включает ожидание лока.** Вызов из другого потока (закрытие вкладок при выходе) ждёт чужой
   долгий вызов не дольше своего `timeout`, затем `CDPTimeout` без отправки кадра. В однопоточной работе агента лок
   свободен — поведение не меняется. `CDPClient.close()` лок не берёт.
3. **`Chrome.close()` в launch** — закрыть ws (рабочий поток сразу получает `ChromeDisconnected`), затем
   terminate → wait → kill; `Target.closeTarget` не шлём — вкладки умирают вместе с процессом.
4. **Свои вкладки в attach/ws.** `close()` закрывает `owned_targets` (только id из своего `createTarget`) с таймаутом
   1 с на вкладку, затем ws; не закрытые остаются в `owned_targets`. `connect()` при живом соединении закрывает только
   сирот — свои вкладки, которые агент уже закрыл, а Chrome не подтвердил; вкладку, с которой идёт работа, не трогает
   (`Chrome` помнит свои `Tab` по targetId). После переподключения сиротами считаются все свои вкладки прошлого соединения.
5. **Проверка фокуса перед вводом** — один `Runtime.evaluate` после клика: `document.activeElement` — сама цель или её
   contenteditable-потомок; самый глубокий активный элемент (через открытые shadow root) — не
   `input[type=password|file|hidden]`. Иначе `StalePage` без ввода. Клик по полю к этому моменту уже был; повтор возможен
   только после нового снимка и нового решения Jev (как и для любого `StalePage`), сгенерированный текст переиспользуется
   при том же контексте. Другие потомки цели (например, `input` внутри `div[role=textbox]`) не принимаются: такой `input`
   сам есть в снимке. Проверка «нет текста для TYPE_TEXT» перенесена до клика.
6. **Логи INFO без персональных данных:** шаг — операция, метка, `len=N`, хост url; текст и полный url — DEBUG.
   `NavigationFailed` называет только хост (текст ошибки попадает в итоговую строку лога INFO).
7. **pyright:** `uvx pyright browser_hands scripts` без venv не видит зависимости (websockets, httpx, mcp — ошибки
   импорта). С `--pythonpath .venv/bin/python` — 0 ошибок. `[tool.pyright]` в `pyproject.toml` не добавлял — файл не
   входит в зону ядра.
8. **Мелкое:** `httpx.Limits(keepalive_expiry=300)` (остальные лимиты — как по умолчанию у httpx: 100/20), чтобы прогрев
   при старте доживал до первого `browse`. Chrome в launch запускается с копией окружения без `*_API_KEY` и
   `OPENROUTER_API_KEY`.

## Исправления после ревью — обвязка, 25.09.2026

1. **Отмена.** `BrowseService.browse(..., cancel: threading.Event | None = None)`. Инструмент `browse` создаёт своё
   событие на каждый вызов; на `anyio.get_cancelled_exc_class()` выставляет его и пробрасывает исключение. Сразу после
   захвата лока выставленное событие даёт `failed: cancelled` без агента. Вторая проверка — после `connect()`: в attach
   подключение может ждать «Разрешить» до 60 с. Фабрика агента получает keyword `cancel=` (интерфейс с Пакетом 1). До
   слияния с ядром, где `Agent` принимает `cancel`, живой `browse` в одной `feat/shell` падает на `TypeError`;
   тесты идут на фейках. `FakeAgent` ведёт себя как ядро: выставленный `cancel` → `failed`, `error="cancelled"`.
2. **Потолки** `MAX_STEPS_LIMIT = 50`, `TIMEOUT_LIMIT_S = 300` в `config.py`. Проверяются в схеме MCP (`le`), в
   `from_env`, в `apply_overrides` (флаги CLI и bench) и в `validate()` — для `Settings`, собранных в обход env.
3. **Завершение.** `close(wait_s=3)` сначала выставляет `_closed` и события отмены всех прогонов (идущего и ждущих),
   потом ждёт лок. `abort()` = `close(wait_s=0)`, лок не ждёт. Обработчик сигнала `serve` вынесен в
   `cli._stop_handler`: `abort()`, удаление временного профиля, `os._exit(0)`. Повторный сигнал во время закрытия
   только пишется в лог, потому что Python вызывает обработчик вложенно. Не решено в обвязке: если сигнал придёт,
   пока `browse` создаёт Chrome (`_ensure_chrome` → `connect()` в launch), процесс может остаться. Это дело
   `Chrome.close()` во время `connect()`.
4. **Ключ не в логах.** `logging.quiet_http_loggers()` ставит `hpack`, `h2`, `httpcore`, `httpx` на
   `max(level, WARNING)`. Вызывается при первой настройке логгера пакета и в `build_server` после `FastMCP(...)`.
   Тест — подпроцесс с `BROWSER_HANDS_LOG=DEBUG`: корень на DEBUG, эти логгеры ≥ WARNING, строка
   `authorization: Bearer …` в stderr не попадает. Без исправления она попадает (проверено вручную).
5. **Схемы url.** Схема — регулярка `^[a-z][a-z0-9+.-]*:`, кроме «хост:порт» (`localhost:8000`,
   `example.com:8080/x` → `https://`). Разрешены `http` и `https` без учёта регистра и ровно `about:blank`; пустой url
   → `failed: пустой url`. Проверка идёт до лока, поэтому Chrome и вкладка не создаются. Ограничен только стартовый
   адрес, переходы внутри прогона — дело ядра.
6. **`OPENROUTER_API_KEY` — только для openrouter.ai.** `from_env` подставляет его, только если
   `urlsplit(url).hostname == "openrouter.ai"` (не `openrouter.ai.evil.test` и не путь `/openrouter.ai`). Ошибку
   бросает `validate()`, а не `from_env`: `serve` стартует и отвечает на `browse` текстом, как при отсутствии ключа.
   Текст: «нет ключа: задайте BROWSER_HANDS_JEV_API_KEY (BROWSER_HANDS_JEV_URL ведёт на <хост>); OPENROUTER_API_KEY
   отправляется только на openrouter.ai».
7. **Логи.** На INFO — `url_host(url)`; полный url и `goal` — на DEBUG. В сообщении об отклонённой схеме — только схема.
8. **README:** плейсхолдер `<путь к клону>`, регистрация через `"$(pwd)"` из каталога клона, уточнение про `.env`
   у FastMCP (`FASTMCP_*`), раздел «Безопасность и приватность», новое поведение отмены, потолки, схемы url.
9. **`docs/plan.md`:** пути заменены на `<исходник jev-ultrafast>` и `<путь к клону>`, «на маке» — на «локально»,
   строка про отдельную машину переписана без имён. Личные пути остались в файлах Пакета 1: `docs/core-notes.md:8`,
   `scripts/live_wikipedia.py:3`.

## Вкладка пользователя (feat/reuse-tab), 25.09.2026

План — `docs/plan-reuse-tab.md`. Отклонения при реализации:
- Ядро: `find_user_tab(url)` вместо `(host)` (точный url выбирается первым; `about:*` не совпадает по хосту); размерная
